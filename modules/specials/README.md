# 专题（specials）

大会、车展、科技日这类**多个独立事件**的容器。它复用了事件页的阅读样式，但不属于 `stories`：
一场大会里的每个发布仍然各自是 story，各自上热点、进日报；专题只把它们放在一个页面里。

## 流程

1. 后台「专题」页扫描最近 14 天的公开标题，找出被 **至少 3 篇报道、3 个独立来源**提到的大会/峰会/论坛/发布会/车展/科技日。
2. 编辑确认名称、别名和起止日期后创建专题（默认草稿），审核后发布。
3. 发布后按 **别名 + 日期窗口 + 标题/摘要/正文前 4000 字**自动匹配公开报道；之后每 10 分钟补一次。
4. 编辑可以手工加入报道，或把某篇移出；移出的报道进入排除表，自动匹配不会再把它加回来。
5. 成员事件变化后，后台任务用成员事件的标题/综述生成专题综述；页面只读数据库，不触发模型。

## 页面与接口

- `/specials`：已发布专题列表。
- `/specials/:slug`：专题详情，含综述、事件时间线、全部报道、参与来源。
- `/hot` 和 `/specials` 顶部的「热点 / 专题」切换；专题不进热点榜。
- `GET /api/specials`、`GET /api/specials/:slug`：公开读取，只返回 `published` 专题和公开报道。
- `/admin/specials`：候选、手工新建、已有专题。
- `/admin/specials/:id`：编辑名称/别名/日期/导语/封面、发布、重新匹配、重写综述、加入/移出报道。

## 匹配口径

- 专题标题本身自动算一个别名；别名不区分大小写，按子串匹配。
- 日期窗口按北京时间整天计算，包含开始日和结束日。
- 只匹配公开且 `eligible` 的报道；撤回的报道会自动从页面消失。
- 标题里没有大会名、但确实是在大会现场发布的报道，自动匹配不到时由编辑手工加入；这是当前有意保留的人工口子。

## 数据
